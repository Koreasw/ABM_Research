## 1. 일반화된 비용 모델

임의 시나리오·임의 type t·고객-매장(pickup→drop) 거리 D(m)에 대한 **주문당 제공업체 비용**:

```
Cost_t(D) = (w_R_t / 3600) · ( D / speed_t + service_t )
          = slope_t · D  +  intercept_t

  slope_t     = w_R_t / (3600 · speed_t)     [KRW/m]  … 거리 1m당 한계비용
  intercept_t = w_R_t · service_t / 3600     [KRW]    … 거리무관 인도 고정비용
```

파라미터 대입 예시 **(K50_1 파라미터 예시 — fixed_cost=(5000,5000,5000) 조합; 다른 조합 수치는 §0.2 자동생성 표)**:

| type | slope (KRW/m) | intercept (KRW) |
|------|--------------:|----------------:|
| BIKE | 0.4200 | 266.7 |
| WALK | 1.3650 | 216.7 |
| CAR  | 0.6562 | 500.0 |

occupied 시간(재고 복귀 스케줄용): `busy_t(D) = D / speed_t + service_t`
(건물 도착까지의 편도 이동 + 인도시간; 왕복 모델링 시 `2·D/speed_t + service_t`로 치환).

## 2. 지배·교차거리 이론 (파라미터 바뀌면 이 식으로 재계산)

**교차거리** (두 type a,b의 비용이 같아지는 거리):

```
D*(a,b) = ( intercept_b − intercept_a ) / ( slope_a − slope_b )
```

**완전 지배**: a가 모든 D≥0에서 b보다 싸다  ⟺  `slope_a ≤ slope_b` **AND** `intercept_a ≤ intercept_b`.

### 2.1 불변 정리 — BIKE의 CAR 완전지배 (data1 전 조합, 2026-07-10 실측)

speed·var_cost·service_time은 전 시나리오 상수(§0)이므로, BIKE-CAR 지배 조건은
w_R 비율만의 부등식으로 축약된다:

```
BIKE ⊒ CAR  ⟺  w_B/w_C ≤ min( speed_B/speed_C , service_C/service_B )
            =  min( 1.25 , 1.5 ) = 1.25   (slope 조건이 binding)
```

(speed_B/speed_C = 5.291005…/4.232804… = **정확히 1.25** — §0 표의 speed는 소수 3자리 반올림 표기.)

관측된 w_B/w_C 최댓값은 12,000/10,000 = **1.20** (fixed_cost=(9000,·,5000) 조합들) < 1.25.
→ **11개 fixed_cost 조합 전부에서 BIKE가 CAR를 완전지배** (`D*(B,C) < 0`, D≥0 교차 없음).
따라서 **BIKE 재고가 있는 한 CAR는 어떤 거리에서도 1·2순위 경쟁에서 BIKE를 이길 수 없다.**

**유효범위 단서 (정직성 조항)**: 이 정리는 data1 관측 조합에 대한 **데이터-전역(data-wide)
불변**이지 파라미터-보편 법칙이 아니다. 여유가 작다(1.20 vs 1.25): 예컨대 fixed_B=9,000에서
fixed_C가 4,600 미만이면 slope 조건이 깨져 원거리 BIKE↔CAR 교차가 생긴다. 새 데이터셋에는
§9 절차로 재판정하며, V-RIDER 테스트가 전수 감시한다.

### 2.2 교차 구조 — 유효 교차점은 정확히 둘, 순서는 강제

다음 세 조건 아래에서 — **관측 8개 조합 전부 성립** —

- **(C1)** BIKE ⊒ CAR (§2.1),
- **(C2)** `intercept_W < intercept_B` ⟺ `w_W < w_B` (service_W = service_B = 120 s이므로 동치;
  관측 최대비 w_W/w_B = 0.864),
- **(C3)** `slope_W > slope_C` ⟺ `w_W/w_C > speed_W/speed_C = 0.3125` (정확값; 관측 최솟값 0.45),

유효 교차점은 정확히 `D*(B,W)`·`D*(W,C)` 둘이고 순서가 유도된다: `0 < D*(B,W) < D*(W,C)`.

*증명*: C2로 D=0에서 WALK 최저, C3(⇒ slope_W > slope_B)로 WALK가 BIKE를 한 번 교차(D*(B,W)>0).
그 지점에서 `Cost_W = Cost_B < Cost_C` (C1의 강한 부등식) — 즉 WALK는 아직 CAR보다 싸다.
`Cost_W − Cost_C`는 slope_W > slope_C로 강증가하므로 이후 정확히 한 번 교차: `D*(W,C) > D*(B,W)`. ∎

조합별 경계 수치(D\*(B,W) 35~413 m, D\*(W,C) 183~1212 m)는 **§0.2 자동생성 조합표** 참조 —
수기 계산 금지, `analysis/rider_assignment_tables.py` 재실행으로 갱신한다.

**경계 tie-break**: D = D\* 정확히에서 두 type 비용이 같으면 코드는 type명 사전순
(`type_priority` key = (cost, type); BIKE < CAR < WALK)으로 순위를 깬다.

## 3. 거리 구간별 비용 우선순위 — 구조는 보편, 경계는 조합별 (핵심 일반화 결과)

§2.2 조건 C1~C3 아래에서(관측 8개 조합 전부 성립) capa·재고를 무시한 **순수
비용순 정렬**은 **정확히 세 구간**으로 나뉜다:

| 거리 구간 | 비용 오름차순 우선순위 (싼 것 → 비싼 것) |
|-----------|------------------------------------------|
| `0 ≤ D < D*(B,W)`        | **WALK → BIKE → CAR** |
| `D*(B,W) < D < D*(W,C)`  | **BIKE → WALK → CAR** |
| `D > D*(W,C)`            | **BIKE → CAR → WALK** |

- **구조는 보편**: BIKE⊒CAR 지배(§2.1)로 순위 변화는 WALK의 위치 이동뿐 —
  근거리일수록(낮은 고정비) WALK가 앞으로, 원거리일수록(느린 속도) 뒤로 밀린다.
  이 3단 구조 자체는 8개 조합 전부 동일하다.
- **경계는 조합별로 크게 이동**: D\*(B,W) ∈ [35, 413] m, D\*(W,C) ∈ [183, 1212] m
  (§0.2 자동생성 표). 구판의 "53 m / 400 m"는 fixed_cost=(5000,5000,5000) **한 조합**
  (28개 중 9개 시나리오)의 값을 전체로 잘못 일반화한 것이다.
- **WALK 1순위는 실재한다**: 전 주문의 **1.7% (87/5,200)**. 특히 (9000,4000,5000)
  조합(K300_2·K300_4·K300_6)은 **413 m까지 WALK 1순위**, 635 m까지 WALK가 CAR보다 우위다.
  *(2026-08-04 모집단 변경 주의: 이전 판은 3.3%(417/12,450)였고 상한 조합도
  (9000,3000,5000)·794 m였는데, 그 조합은 K1000 계열에만 있어 코퍼스 밖으로 나갔다.
  WALK 1순위가 줄어든 것은 규칙이 바뀌어서가 아니라 **모집단에서 고K 시나리오가
  빠졌기 때문**이다.)*
  구판의 "실측 D≥181m ≫ 53m이므로 실무상 2·3행만 발생"은 K50_1 전용 관찰의
  잘못된 일반화였다 (개정 2026-07-10, 근거: `analysis/rider_assignment_tables.py`).

## 4. 재고(차감/복귀) 상태 모델

H0의 "무한 공급"을 **type별 유한 풀**로 대체한다.

- **상태**: `free_t(τ)` = 시각 τ에 가용한 type t 라이더 수. 초기 `free_t(0) = N0(t) = ρ_t·K`.
- **차감**: 주문 배정 시 `free_{t*} −= 1`.
- **복귀**: 배정된 라이더는 `τ + busy_{t*}(D)` 시각에 풀로 복귀 → `free_{t*} += 1`.
  (busy 정의는 §1. 왕복/재배치 시간은 파라미터로 확장 가능.)
- 이로써 "가용 BIKE가 모두 배달 나감" = `free_BIKE(τ) = 0` 상태가 자연히 발생하고,
  그때 비용 차순위 type으로 **fallback**된다.

## 5. 일반화된 배정 알고리즘 (capa 필터 → 비용순위 → 재고 cascade)

주문 i (부피 V, 거리 D, 도착시각 τ)에 대해:

```
1. 적재가능(capa) 필터:      E = { t : capa_t ≥ V }
                              E 가 공백이면(최대 capa < V) → ValueError (배차 불가)

2. 거리 구간으로 비용 우선순위 결정 (§3):
      D < D*(B,W)   → [WALK, BIKE, CAR]
      D < D*(W,C)   → [BIKE, WALK, CAR]
      else          → [BIKE, CAR, WALK]
   (경계 수치는 조합별 — §0.2 표. 파라미터가 바뀌면 §2 식으로 교차거리·순위 재생성)

3. 재고 cascade: 위 우선순위를 따라가며
      첫 번째로 (t ∈ E) AND (free_t(τ) > 0) 인 type t* 를 선택
      → free_{t*} −= 1,  복귀이벤트 schedule(τ + busy_{t*}(D))

4. 우선순위 내 가용 라이더가 하나도 없으면 → 대기(queue) 또는 정책상 최저비용
   가용 type이 생길 때까지 지연 (모델 선택지, §7)
```

즉 **"capa로 후보를 거르고, 거리로 비용순위를 매기고, 재고가 있는 가장 싼 후보를
집는다"**. 재고가 무한하면 3단계에서 항상 1순위가 잡혀 §3의 argmin 규칙(=현행
비용최소 규칙)으로 정확히 붕괴한다.

## 6. 결과로 도출되는 (거리 D, 부피 V) 배정 지도

### 6.1 재고 여유 시 (1순위 항상 가용)

```
V > 100                    → CAR    (capa 강제: BIKE 100 초과)
V ≤ 100 & D ≥ D*(B,W)      → BIKE   (BIKE가 CAR 완전지배 + WALK보다 우위)
V ≤ 70  & D < D*(B,W)      → WALK   (초근거리 고정비 우위; 경계 수치는 조합별 — §0.2 표)
```

WALK 1순위는 전 주문의 **1.7%(87/5,200, capa-무시 기준)** 실재하며, 특히 D\*(B,W)가
큰 조합(최대 413 m, fixed_cost=(9000,4000,5000)·(9000,4000,6000))에서 다수 발생한다.
capa를 적용한 재고여유 배정에서도 WALK가 같은 수로 배정된다(§8 표, 합계 87건 —
28개 코퍼스에는 WALK 1순위이면서 VOL>70인 주문이 하나도 없어 capa 필터가 아무것도
깎지 않는다. 38개 모집단에서는 417 vs 411로 갈렸다).

### 6.2 BIKE 소진 시 (`free_BIKE=0`) — WALK vs CAR 거리 규칙

```
V > 70                     → CAR    (WALK capa 70 부족)
V ≤ 70 & D ≥ D*(W,C)       → CAR    (거리 한계비용 우위)
V ≤ 70 & D < D*(W,C)       → WALK   (고정 인도비용 우위)
```

교차거리가 D\*(B,W)→D\*(W,C)로 넓어지는 이유 (예: fixed_cost=(5000,5000,5000) 조합의
53→400 m): 경쟁 상대가 (BIKE 대신) CAR의 큰 고정비로 바뀌어 WALK의 저고정비가 더 오래
우위를 유지하기 때문 (§1 K50_1 예시: CAR intercept 500.0 ≫ BIKE intercept 266.7이므로
WALK intercept 216.7의 우위가 CAR와 비교할 때 더 멀리까지 지속됨).

### 6.3 BIKE·WALK 동시 소진 시

남은 후보는 CAR뿐 → 무조건 CAR (capa 200으로 전 주문 수용).

## 7. 재고 고갈 시 정책(구현 선택지)

우선순위 내 가용 라이더가 0일 때의 처리 — 시나리오/연구목적에 따라 선택:

| 정책 | 동작 | 비고 |
|------|------|------|
| **A. 지연배차(queue)** | 가장 싼 type의 라이더가 복귀할 때까지 대기 | 비용최소 유지, deadline 위반 위험 |
| **B. 즉시 fallback** | 순위상 다음 가용 type 즉시 배정 | 지연 0, 비용 상승 |
| **C. 하이브리드** | deadline 여유 있으면 A, 임박하면 B | deadline_sec 활용 |

H0 확장 기준값으로는 **B(즉시 fallback)** 권장 — §5 알고리즘이 그대로 이에 해당하며
"무한 공급 → 유한 재고" 변경의 최소 확장이다.

## 9. 파라미터가 바뀌면 (일반화 절차)

라이더 파라미터가 현재 값과 다른 데이터셋에도 본 규칙을 적용하려면:

1. §1로 각 type의 `slope_t, intercept_t` 재계산.
2. §2 교차거리 `D*(a,b)`를 모든 쌍에 대해 계산, 완전지배 관계 판정.
3. 유효 교차점들이 거리축을 나누는 구간마다 §3 형태의 **비용 우선순위표** 재생성.
4. capa·초기재고(`N0=ρ·K`)와 함께 §5 알고리즘에 투입.

지배·순위·교차거리는 **파라미터만의 함수**이므로 시나리오(K·거리·VOL 분포)가 아무리
달라도 위 4단계로 규칙이 결정된다.

이 절차는 문서상의 지침이 아니라 **프로덕션 코드가 실제로 하는 동작 그 자체**다 —
`type_priority`는 매 호출마다 그 시점 파라미터의 slope/intercept에서 순위를 도출하므로,
`fixed_cost` 조합이 바뀌어도(§0.2) 코드 수정 없이 위 4단계가 자동으로 실행된다. 문서
표(§0.2·§0.3·§8)도 `analysis/rider_assignment_tables.py`를 재실행하기만 하면 갱신된다.

정적 사전확정 구조는 더 이상 존재하지 않는다.

## 11. 층 배정과의 관계 (2026-07-10 확정)

층 배정(인구밀도 프로파일 범주형, `etc/demand_mapping.md`, 2026-07-10 확정)은 2D 거리와 완전 독립이고, 라이더 배정만 실제 도로거리 D의 경제성 함수다. 구(v4~v6 계획) 방식에서 존재하던 '원거리 주문 → 고층 ∧ 원거리 타입 우선순위'의 구조적 상관이 제거되어, 층↔라이더타입 교락(confounding) 없이 배정 효과를 분석할 수 있다.
