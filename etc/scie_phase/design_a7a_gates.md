# A7-a 게이트 보강 설계 — B12~B18 (2026-08-11, Fable 5)

> **지위**: A7-a의 설계 정본. Fable 투입 계획(구현 로그 §A5-d) 2순위 수행 결과.
> 입력 = §A5-c-④ 이월 8건 중 A7 대상 5건 + F3 이월(`_ops_span` 경계) + A6 이월 3
> (deny 참조점). §A5-c-④의 6·7·8(공용화·이름 이중화·실구동 테스트)은 **Phase B 유지**.
> 구현은 본 설계 승인 후 별도 세션(권고: 오퍼스/high)에서 수행한다.
>
> **설계 원칙 (A5-c의 교훈)**: 게이트는 자기 위협 모델을 스스로 증명해야 한다 — 각 게이트
> 명세에 "이 조작이 지금은 PASS지만 이후 FAIL해야 한다"가 명시되고, 그 조작이 그대로
> **음성 회귀 테스트**로 핀된다. SKIP은 시끄럽게(A13 전례), 신설 게이트는 원칙적으로
> SKIP 없음(전부 신규 산출물 대상). 번호는 B6 결번 관행을 유지, **B12부터** 신설한다.

## B12 — 주문 결과 정합·하한 (🔴 우선 / §A5-c-④ #3)

**위협 모델**: `t_e2e_mean_sec = 1.0`으로 변조해도, `sla_violation`을 전건 반전해도
현재 10/10 PASS — **논문 주 지표가 무게이트**.

| 세부 | 판정식 | 근거·데이터 |
|---|---|---|
| B12-1 집계-원천 재계산 | `t_e2e_mean/p95_sec`·`t_building_order_mean/p95_sec`·`t_order_post_handoff_*`를 `per_order`(`ord_time_abs_sec`→`delivered_at_sec`)와 레그 레코드에서 **재계산해 FLOAT_TOL 일치** | 집계 필드 변조는 원천과의 불일치로 검출. per_order 원천 자체의 변조는 B2(택배원 체인)·B15(상류 체인)가 잡는다 — 3중 교차 |
| B12-2 SLA 논리 정합 | per-order로 `sla_violation ⇔ (t_e2e > SLA 임계)` 재검증, `n_sla_violations` = 재계산 합, `sla_violation_rate` = 합/`n_delivered` | SLA 임계는 config 정본에서. 전건 반전 조작이 검출됨 |
| B12-3 물리 하한 | per-order `t_building_order ≥ handoff_sec`(60 s, config 정본) | 인계만으로도 60 s — 이보다 짧은 건물 구간은 물리 위반 |

**음성 회귀**: ⓐ`t_e2e_mean_sec=1.0` 변조 → FAIL ⓑSLA 전건 반전 → FAIL (§A5-c-④가
실측한 조작 그대로).

## B13 — 워밍업 적정성, H1판 A13 (🔴 우선 / §A5-c-④ #4)

**위협 모델**: `warmup` 블록을 삭제해도 PASS. H1이 차갑게 돌면 EV 대기가 낮게 나와
**H0 대비 우위가 워밍업 인공물**이 된다.

| 세부 | 판정식 | 근거 |
|---|---|---|
| B13-1 존재+길이 | `kpi_summary.simulation.warmup` **부재 = FAIL**(H0 A13은 SKIP이지만 HR 산출물은 전부 R8-b 이후 — SKIP 사유가 원천적으로 없다), `head_sec ≥ 600` | `WARMUP_MIN_HEAD_SEC` 재사용(배경 포화 실측 300~600 s) |
| B13-2 실측 온도 | `util_at_first_order / (고정창 EV 가동률) ≥ 0.35` | H0 임계 재사용 근거: 배경 보행자 프로세스는 **모드 불변**(§3.7 고정창 논거와 동일). 구현 시 HR 4티어×10seed 분포로 0.35가 콜드(정확히 0)와 분리됨만 확인하고 재캘리브레이션은 하지 않는다 |
| B13-3 구조 정합 | `head_sec == min ORD − clock_start`(FLOAT_TOL) | H0 A13-3 이식 — 스냅샷이 선언 창과 다르면 실측이 무의미 |

**음성 회귀**: warmup 블록 삭제 → FAIL(현재 PASS인 조작), `util_at_first_order=0.0`
변조 → FAIL.

## B14 — EV 카별 보존 + 선언 정합, H1판 A6/A11 (§A5-c-④ #1)

**위협 모델**: `EV2.n_alights -= 5`, elevator 블록에서 EV4 삭제 — 모두 현재 PASS.

| 세부 | 판정식 |
|---|---|
| B14-1 카별 보존 | EV별 `n_boardings − n_alights == 0`(종료 시 전원 하차 — B11의 "함대 귀가"와 연동) |
| B14-2 kind 완전성 | EV별 `sum(n_boardings_by_kind.*) == n_boardings` — **F2가 신설한 `robot` 키 포함**. F2 수정("by_kind가 로봇을 누락")의 게이트화 |
| B14-3 선언 정합 | `kpi_summary.elevator`의 EV 집합 == config 정본의 EV 집합(shared+dedicated), 과부족 모두 FAIL |

**음성 회귀**: ⓐ`n_alights -= 5` → FAIL ⓑEV4 항목 삭제 → FAIL ⓒby_kind에서 robot 키
삭제 → FAIL.

## B15 — 상류 체인, H1판 A2/A3/A7 (§A5-c-④ #2)

**위협 모델**: `ready`를 주문보다 1시간 앞으로, 전 주문 `rider_type`을 CAR로 변조 —
모두 현재 PASS. B2는 건물 안 체인만 지키고 **건물 앞 구간이 무방비**.

| 세부 | 판정식 |
|---|---|
| B15-1 시계열 단조 | per-order `ord ≤ ready ≤ dispatch ≤ arrival ≤ entered`(entered 이후는 B2 소관 — 중복 금지) |
| B15-2 도착 재구성 | `arrival == dispatch + horizontal_travel`(H0 A3 이식, 허용 오차 동일) |
| B15-3 풀 배정 리플레이 | rider_type 배정 규칙 재현(H0 A7 이식) |

**설계 결정**: B15-3은 verify_h0의 로직을 **복제-이식**한다(중복 허용). 공용 모듈 승격은
§A5-c-④ #6(_guard 공용화)과 같은 Phase B 사안이므로 여기서 새로 벌이지 않는다 — 단
복제 지점에 `# PHASE-B-DEDUP` 마커를 남겨 통합 대상임을 표시.

**음성 회귀**: ⓐready −3600 s 변조 → FAIL ⓑ전 주문 CAR 변조 → FAIL.

## B16 — floor 범위 (§A5-c-④ #5)

**위협 모델**: floor=1 또는 `n_floors` 초과 레그는 B4가 `NodeNotFound`로 **크래시**한다
(_guard가 CRASH로 잡지만 사유 불투명) — 소유 게이트가 없다.

- **판정식**: 모든 robot leg의 `floor ∈ [2, n_floors]`. F1 수정(assign이 `floor < 2`
  거부)의 **산출물 측 독립 검증** — 생산 코드와 검증기가 같은 규칙을 서로 다른 자리에서
  강제한다.
- **실행 순서 요건**: B16을 B4 **앞에** 배치해 범위 위반이 크래시가 아니라 명시적
  FAIL로 보고되게 한다.
- **음성 회귀**: leg의 floor=1 변조 → **B16 FAIL이고 B4 CRASH 아님**을 둘 다 단언.

## B17 — 캡 종료 검열 정직성 (F3 이월 본체)

**위협 모델**: 캡 종료 런에서 utilization_ops 분모(ops 창)가 마지막 *완결* 이벤트로
수축해 가장 바쁜 최종 구간이 계산에서 빠진다 — 검열된 런이 "안정"으로 읽힌다.

| 세부 | 내용 |
|---|---|
| B17-1 종료 상태 정합 (게이트) | 정상 종료 런: `n_trips_inflight_at_end == 0 ∧ n_requests_queued_at_end == 0`. 캡 종료 런: `n_requests_unserved_at_end == queued + 배정-미완결(미서비스분)` 재계산 정합(F3 수정의 게이트화) |
| B17-2 ops 창 우측 경계 (kpi 정의 변경 + 게이트) | **결정 필요** — ⓐ권고: `ops 창 우측 = min(마지막 운반체 정착, 종료 시각)` — 캡 런에서는 종료 시각까지 확장되어 분모가 실제 가동 시간을 반영. 정상 종료 런은 **수치 불변**(정착 < 종료). ⓑ대안: 현행 유지 + `ops_span_censored` 플래그만 신설. 게이트는 채택안의 규약을 검증 |

⚠️ **A7-b(84 run 전수)는 B17-2 확정·구현 후에 실행할 것** — 정의가 나중에 바뀌면
84 run을 재실행하게 된다. 채택안 ⓐ는 정상 종료 런 수치를 바꾸지 않으므로 기존
기준값(골든패스·게이트 기대값)은 영향 없다.

**음성 회귀**: 정상 종료 결과에 `n_trips_inflight_at_end=3` 주입 → FAIL.

## B18 — board_denied 상한 (A5-⑤-2 해소 + A6 이월 3)

**위협 모델**: 배차·EV 승객 프로토콜 회귀로 deny가 폭주해도 아무 게이트도 없다.

- **판정식**: 티어별 `n_board_denied ≤ 상한`. 티어는 결과의 주문 수(50/100/200/300)로
  판별. **참조점 = A6 10-seed 평균**(K50 13.9 / K100 40.6 / K200 87.0 / K300 109.1) —
  단일 seed 구값(17/73/124)은 폐기.
- **임계 공식(권고)**: `mean + 4σ`(A13 전례 — 불운한 seed의 거짓 FAIL 방지). σ는
  `results/vv/monotonicity_hr.csv`(gate=True 행만 — A6 이월 4 준수)에서 추출, 구현 시
  수치를 이 문서에 기입해 동결한다.
- **스코프**: 프로덕션 코퍼스 전용. 극한 케이스(보행자 ×10에서 737)는 이 게이트의
  대상이 아니다(`tests/test_vv_extreme_hr.py`가 별도 소유).

**음성 회귀**: `n_board_denied`를 상한+1로 변조 → FAIL.
