## §0. 이 Phase를 처음 보는 사람을 위한 배경

Phase A까지 완성된 세계: 라이더가 로비 카운터에서 로봇에게 음식을 넘기는 H1 모드.
로봇이 전부 배달 중이면 라이더는 카운터 앞에서 **상한 없이 선착순(FCFS)으로
기다린다** — 아무 정보 없이. H2는 여기에 **스마트 빌딩의 정보 개입**을 얹는다:

1. 라이더 도착 시 로봇이 모두 바쁘면, **빌딩 관리자(BuildingManagerAgent)** 가 관제의
   로봇 상태로부터 계산한 **예상 대기 시간 W_est**를 라이더에게 알려준다.
2. 라이더는 W_est를 **자신의 유형별 시간단가 w_R**(BIKE/WALK/CAR — 배민 실데이터
   캘리브레이션, STAGE 1)로 대기 비용으로 환산한다: 대기 비용 = W_est × w_R/3600 (원).
3. 대기 비용이 **비용 임계 C_th** 이상이면 큐에 서지 않고 **즉시 직접 배달(H0 방식)로
   전환**한다(사전 판단, balk). 미만이면 H1과 동일하게 대기한다(진입 후 포기는 없음).

H1과 H2의 유일한 차이가 "정보 제공 여부"이므로, 두 모드의 CRN 페어드 차분은
**관리자 정보 개입의 가치**로 곧장 해석된다. 대기 시간을 허비한 뒤 포기하는 구판
renege와 달리 balk 라이더는 대기 손실 없이 전환하므로, H2 라이더 후생 ≥ H1이
구조적으로 성립한다.

이 Phase가 논문에 기여하는 두 가지:

1. **라이더 후생·정보 개입 메커니즘**: balk 전환율(L_rider_balk)은 "로봇 인프라가
   흡수하지 못한 수요"의 직접 지표이며, 유형별 단가 차이로 고단가 유형(CAR)이 먼저
   balk하는 **이질적 행동이 실데이터 단가에서 창발**한다(C2 기여 강화). RQ2 메커니즘
   분해에 "정보 개입" 채널이 추가된다(research_plan §4).
2. **큐잉 이론과의 대조(docking) — 8-step V&V의 마지막 퍼즐**: 구 계획 §7.1의 step 5.
   1차 대조 대상은 **H1**이다 — 무한 인내 FCFS라서 G/G/c 이론 가정(전원 진입·무한
   대기)에 정확히 부합하며, 관측치는 Phase A 배터리 기록을 재사용하므로 추가 실행이
   거의 없다. H2 큐는 C_th 절단으로 이론 가정을 벗어나므로 진입자 조건부 대기로 보조
   대조한다. H0 검증 때는 큐가 없어 이 단계만 미실시로 남아 있었다 — **이 Phase에서
   비로소 실행된다.**

**이 Phase의 필수 용어** (상세: research_plan_scie.md §0):
- **balk (사전 이탈)**: 대기열에 서기 전에 시스템 상태(예상 대기)를 보고 진입 자체를
  포기하는 행동. 큐에 선 뒤 기다리다 떠나는 renege(사후 포기)와 구별된다. H2는 balk만
  모델링한다(renege 없음 — 2026-07-23 확정 #11).
- **W_est (예상 대기)**: 관제가 로봇별 잔여 작업에서 결정론적으로 계산하는 예상 대기
  시간. 관리자 알림의 내용이자 balk 판단의 입력.
- **C_th (balk 비용 임계)**: "기다림 vs 직접 배달"을 가르는 대기 비용 임계(원).
  기본값 = BIKE 시간단가의 10분 등가, 민감도 스윕 {5, 10, 15}분 등가.
- **FCFS** (First-Come-First-Served): 선착순. 대기열의 서비스 순서 규칙.
- **G/G/c (Allen–Cunneen 근사)**: 도착 간격 분포도 서비스 시간 분포도 일반(General)이고 서버가 c대(여기선 로봇 c대)인 대기행렬의 평균 대기시간 근사 공식. 도착·서비스의 변동계수(CV)와 이용률 ρ로 계산한다.
- **정상상태(steady state)**: 대기행렬 이론 공식은 "도착률이 일정하게 유지되어 시스템이 평형에 도달한" 상태를 가정한다. 우리 수요는 점심 피크형(비정상)이라, 이론과 비교할 때는 도착률이 상대적으로 평탄한 구간만 잘라 써야 한다(§2 Step B5).
- **C-게이트**: H2 실행 결과가 자동으로 만족해야 하는 불변식 배터리(A/B-게이트의 H2 버전).

## §1. 목표와 완료 기준

**목표**: `--mode h2`로 알림 기반 핸드오프가 완주하고(balk→H0 전환 포함), C-게이트·
골든패스·배터리를 통과하며, G/G/c 이론 대조(H1 1차 + H2 보조)가 문서화되고, 기존
H0·H1 결과는 무교란.

### ★ H2의 종료 조건 — **분기가 필요 없다** (R8 결정 #24, 2026-08-06)

H1이 `_carriers_settled()`에 "라이더 전원 퇴장 ∧ 로봇 전원 1F 홈"을 넣고 나면,
**H2는 아무것도 더 안 해도 된다.** 그 AND가 주문별 운반체 혼재를 자동으로 처리한다:

```
H2 완료 = 전 주문 배달 ∧ 라이더 전원 건물 밖 ∧ 로봇 전원 홈      (H1과 동일 식)
```

balk로 H0 경로로 빠진 주문은 라이더가 끝까지 배달하므로 첫 두 항에 걸리고, 로봇이
받은 주문은 셋째 항에 걸린다. **주문마다 "누가 배달했는지" 조회할 필요가 없다** —
그런 분기를 넣으면 balk 전환 시점의 경계 조건을 매번 다시 따져야 하고, 그게 정확히
피하려던 복잡도다.

⚠️ **C-게이트를 짤 때 A6/A11의 교훈을 그대로 가져올 것**: 종료가 배경 보행자를 안
기다리므로 **보행자가 EV에 탄 채로 끝날 수 있다.** "완료"를 단언하지 말고 **"보존"**을
단언하라 — `boardings − alights == 종료 시점 탑승 인원` 형태다. 구 등식
(`boardings == alights`)은 drain-all에서만 성립하고 지금은 **정상 run을 전건
FAIL**시킨다(H0에서 실제로 그랬다: 실측 EV1 228 대 226).

**완료 기준**:
1. 전체 스위트 green + **H0·H1 비트 동일성**(Phase A 골든패스·결정성 테스트 바이트 일치).
2. Step B0 잔여 설계 동결 문서화 + 사용자 확인.
3. H2 골든패스 2케이스 0-tick 일치(balk 체인 포함).
4. C-게이트(C1~C9) **코퍼스 28 시나리오 × 3 seed = 84 run** 전수 PASS *(구 38 — 결정 #21)*.
5. G/G/c 대조 리포트(H1 1차 ±20% 판정 + H2 보조, 부합/비부합 구간과 논거) 산출.
6. 단조성·극한 PASS(**C_th=∞ ⇒ H2≡H1 비트 동일** 포함), 진행 로그 기록.

### Step B1 — 알림·balk·무상한 큐 구현 (배정: 오퍼스 / high, ~2~2.5일)

1. `lobby_queue_zone`(그래프에 이미 예비된 노드) 위에 **무상한** FCFS 대기열 구현 —

2. 관제(control_system)에 W_est 계산 유틸(B0-2 산식) + BuildingManagerAgent 알림
   이벤트 발신(주문 기록에 `w_est_sec` 스탬프).
3. `HandoffRiderAgent` 상태 확장: WALK_TO_QUEUE → (도착 tick 판단 B0-1) → WAIT_QUEUE →
   (매칭 시) HANDOFF → WALK_TO_EXIT / (balk 시) **FALLBACK_H0** — balk 시점부터 H0
   라이더와 동일한 FSM(EV 선택 → 상행 → 배달 → 하행 → 퇴장)을 탄다. 타이머·포기
   로직은 없다. Phase A의 `rider_cls` 배선 덕에 신규 클래스 없이 상태 확장으로 처리.
4. 배차 확장: 로봇 가용 이벤트 → 큐 선두 매칭(B0-3). 모드 게이트에서 `H2_QUEUED`
   허용(내부 enum 명칭은 코드 호환상 유지 — 논문 표기만 Informed), 종료 조건 확장
   (큐 비움 + balk 라이더의 배달 완료까지).

**산출물·검증**: 구현 + 단위 테스트, K50_1 `--mode h2 --audit` 스모크 완주. H0·H1
비트 동일 확인.

- C1 **큐 보존**: 카운터 도착 수 = 즉시 인계 + 큐 진입 + balk; 큐 진입 수 = 인계 수(포기 없음)
- C2 **FCFS 무위반**: 기록으로부터 인계 순서를 재구성해 진입 순서와 대조, 위반 0 (구판 유지)
- C3' **balk 정합**: 모든 balk 건에서 balk_cost ≥ C_th, 모든 진입 건에서 < C_th — 유형별 단가로 재계산 대조; balk는 전 로봇 busy 상태에서만 발생 (구판 C3 "포기 시각 정합" 대체)
- C4' **W_est 결정론 재현**: 기록의 `w_est_sec`를 로봇 상태 로그로부터 재계산해 일치 — B0-2 산식의 재현성 검증 (구판 C4 "큐 길이 ≤ 8" 대체; 큐 길이는 p95 report-only)
- C5 **fallback 체인 정합**: balk 라이더의 이후 기록이 H0 라이더 불변식(A-게이트 해당 항목)을 만족 (구판 "포기 라이더" → "balk 라이더")
- C6~C9: B4·B5·B8·B9(기구학·분해·윈도우·프로파일)의 H2 버전 (구판 유지)
음성 케이스 테스트 포함(`tests/test_verify_h2.py`).

### Step B4 — H2 골든패스 2케이스 (배정: 오퍼스 / medium, ~1일)

**무엇을**: ①주문 2건 × 로봇 1대 — 두 번째 라이더의 W_est 수기 계산이 임계 미만이라
큐 진입, 대기 후 매칭되는 기본 체인(W_est·대기 시간을 수기 계산) ②주문 1건 × 로봇
장기 점유(인위 점유) — W_est 수기 계산 ≥ 임계 ⇒ balk ⇒ H0 전환 ⇒ 직접 배달 완료까지
전 체인 0-tick 대조. **두 케이스 모두 라이더 유형 단가를 수기 계산에 포함**한다.
`test_vv_golden_path.py` 인프라(합성 시나리오 빌더·보행자 0·단일 층 프로파일) 재사용.

### Step B5 — G/G/c 큐잉 이론 대조: H1 1차 + H2 보조 (배정: 오퍼스 / high, ~1~1.5일)

**왜**: 이 Step은 코드가 아니라 **수학이 본체**다(구판 동일 — Allen–Cunneen 항 추정과
정상상태 절단은 대수·통계 판단이라 상위 모델 high effort). 개정 핵심: 1차 대조 대상이
**H1**이다 — 무한 인내 FCFS·전원 진입이라 이론 가정에 정확히 부합하고, 관측치는
**Phase A 배터리·페어드 기록을 재사용**하므로 신규 실행이 거의 불요하다. H2는 C_th
절단 큐라서 보조 대조로 강등하고, 절단이 만드는 편향(긴 대기 표본의 우측 꼬리 제거 →
관측 대기의 하향 편향)을 명시 보고한다.

**무엇을**:
1. `analysis/ggc_docking.py` 구현:
   - 관측측 1차: **H1** 기록에서 카운터 대기시간 평균(정상상태 구간 한정) 추출.
   - 관측측 보조: H2 기록에서 **진입자(non-balk)의 조건부 대기** — 이론 가정 위반
     (상태 의존 진입 절단)과 편향 방향을 논거로 명시.
   - 이론측: Wq ≈ (ρ^√(2(c+1)) / (c(1−ρ))) · ((Ca²+Cs²)/2) · (1/μ) — c = 로봇 대수,
     μ = 서비스율. **실효 서비스 시간 = 인계 + 로봇 왕복 점유**로 정의해야 함을
     명시적으로 유도·문서화(구판 유지), Ca·Cs = 도착·서비스 변동계수(기록에서 추정).
   - **Ca²는 반드시 실측치를 쓴다 — 포아송(Ca²=1) 가정 금지**(2026-08-03 진단,
     아래 §4-4). ⚠️ **2026-08-04: 값도 경로도 재산출 대상이다.** 구 표기
     `analysis/h0_insights/tables/scenario_summary.csv`의 `arrival_ia_cv2`(H0 라이더
     건물 도착 기준)는 **R0 아카이브로 이동**했고(현 위치
     `archive/h0_v1/analysis_outputs/h0_insights/tables/`, 읽기 전용) **그 값은 v1
     조건**이다. **B5 착수 시 v2 H0 기록에서 건물 도착 Ca²를 재추정**해 이론측 입력으로
     쓴다 — H1/H2에서는 같은 방식으로 카운터 도착 기록에서 재추정한다.
     **원시 주문 프로세스의 CV²를 Ca²로 오용하지 않는다** — 둘은 다른 프로세스다
     (v2 원시값은 `results/h0_stats/scenario_traits.csv`의 `ia_cv2`, 코퍼스 범위
     **0.82~2.26**).
   - 정상상태 구간 규약: 라이더 도착률의 이동 평균이 피크의 ±25% 이내로 유지되는
     최장 구간(구판 유지, 규약 상수 문서화·민감도 확인).
2. K ∈ **{100, 200, 300}** × 로봇 {2, 3}에서 이론 vs H1 관측 대조표 산출 *(2026-08-04:
   구 {100,300,500}에서 K500이 코퍼스 밖 — 결정 #21)* — **±20% 이내면
   부합**. 비부합 구간은 실패로 감추지 않고 비정상성(피크 도착)의 이론 가정 위반을
   논거로 투명 보고(논문 V&V 절의 서사). H2 보조 대조는 같은 격자에서 조건부 대기로
   병기.
3. **Ca² 민감도를 대조표에 병기한다**: 실측 Ca²는 시나리오 간 편차가 크므로(같은 K
   안에서도 배수 차이 — 분산 분해상 c_a²는 **68%가 시나리오 패턴 분산**), 격자의 각
   칸을 시나리오 1개로 대표시키면 ±20% 판정이 시나리오 추첨 운에 좌우된다. 각 K에서
   최소 3개 시나리오(저·중·고 Ca²)로 대조하고 이론값의 범위를 함께 보고한다.

**산출물**: `results/scie/ggc_docking.csv` + 해석 노트 `etc/note_ggc_docking.md`.

### Step B6 — 단조성·극한 (배정: 소넷 / low~medium, ~0.5일)

**무엇을**: 단조성 — ①C_th ↑ ⇒ balk율 ↓ ②로봇 수 ↑ ⇒ balk율·큐 대기 ↓ ③K ↑ ⇒
balk율·큐 길이 ↑ ④유형별 balk율 순서 = 시간단가 순(CAR ≥ BIKE ≥ WALK — face validity).
극한 — **C_th=∞: H2 ≡ H1 비트 동일**(balk 0건이면 동일 난수 스트림이라 바이트 일치
요구 — 알림·balk 배선이 H1 경로를 오염시키지 않았다는 강력한 자기 검증),
C_th=0: 전 로봇 busy 도착자 전원 즉시 H0 전환(대기 없는 절단 — balk 경로 전수 검증).

**무엇을**: H2로 **28 × 3 seed = 84 run** 전수, C-게이트 인라인 PASS. wall time 실측 기록.

## §4. 리스크·주의점

1. **W_est 추정 품질이 balk 판단을 좌우**: 산식(B0-2)은 결정론·재현 가능으로 동결하고
   (C4' 게이트가 검증), 예측 오차(예상 vs 실현 대기)는 감추지 않고 report-only 지표로
   공개한다 — 오차 분포 자체가 "정보 품질" 논의 재료(부록 figure 후보).
2. **G/G/c 비부합 가능성**: 피크형 도착의 비정상성은 여전하다(구판 동일). 1차 대상을
   이론 정합적인 H1로 옮겨 리스크 자체를 줄였고, 비부합 구간은 논거와 함께 투명 보고
   (research_plan_scie.md §10.1).
3. **C_th=∞ 극한의 자기 검증**: H2≡H1 비트 동일이 실패하면 알림·balk 배선이 H1
   경로를 오염시킨 것 — fallback 구현 버그의 조기 검출기(구판 τ=0 극한을 대체하는
   더 강한 성질).
4. **도착 burstiness 증폭 — 포아송 가정은 대기를 크게 과소평가한다**(2026-08-03
   H0 진단). 원시 주문 프로세스의 도착간격 CV²는 대체로 ~1(포아송 수준)이지만,
   **풀 배차 대기와 거리 이동을 거친 뒤 건물에 도착하는 프로세스의 CV²는 크게
   증폭**된다. Allen–Cunneen 근사에서 Ca²는 Wq에 선형으로 들어가므로, Ca²=1을
   가정하면 카운터 대기를 수 배 과소 예측한다. 이 진단은 Step B5의 이론측 입력
   규약(위 §2 B5-1)으로 반영돼 있으며, H1 관측치와 이론값이 어긋날 때 **가장 먼저
   의심할 원인**이다.

   > ⚠️ **2026-08-04 정정 — 인용하던 수치와 경로가 둘 다 무효다.**
   > ① 구 인용값("원시 0.82~2.83 / 건물 도착 0.87~8.9, 극단 **17.9(K1000_1)**,
   > 증폭은 K200부터 뚜렷")은 **v1 조건·38 시나리오 측정**이고, 극단값의 출처인
   > **K1000은 코퍼스 밖**(결정 #21)이라 **재현 불가**다.
   > ② 정본 경로 `analysis/h0_insights/note_h0_demand_insights.md`와 `tables/*.csv`는
   > **R0 아카이브 때 이동**했다 → 현 위치
   > **`archive/h0_v1/analysis_outputs/h0_insights/`**(읽기 전용).
   > **v2에서 할 일**: 건물 도착 CV²는 **아직 v2로 재산출되지 않았다** —
   > Step B5 착수 시 **가장 먼저 재측정**할 것. 현재 v2 자료로 확인 가능한 것은
   > *원시* 도착간격 CV²뿐이며(`results/h0_stats/scenario_traits.csv`의 `ia_cv2`),
   > 코퍼스 내 최대는 **K200_9 = 2.26**, 이어서 K200_6 1.97 · K100_6 1.94다.

   > `--tier all`로 재생성하되 **끝나고 primary로 되돌릴 것**.)

5. **balk·알림은 burst 시나리오에 집중 발생할 것**: 도착이 뭉치면 그 순간 전 로봇이
   busy가 되어 W_est가 튀므로, balk 전환은 평균 부하가 아니라 **버스트 순간에
   몰린다**. C_th 캘리브레이션(B0-4)과 B6 단조성 ③(K↑ ⇒ balk율↑) 판정 시 **고 Ca²
   시나리오를 반드시 표본에 포함**할 것 — 저 Ca² 시나리오만 보면 메커니즘이 거의
   발화하지 않아 "구현이 안 된 것처럼" 보일 수 있다.

   > **2026-08-04 정정**: 구 권고 표본 **K1000_1은 코퍼스 밖**이다. v2 대체 표본 =
   > **K200_9**(원시 CV² 2.26, 코퍼스 최대) — 단 이는 원시 기준이므로, 건물 도착
   > CV²를 B5에서 재측정한 뒤 그 순위로 확정할 것. **부하 자체를 더 세게 걸어야 하면
   > K를 올리는 대신 보행자 30/분 러시를 쓰는 편이 싸고 확실하다**(W4a 실측: EV 4대
   > 전부 가동률 0.996~0.999로 포화). 구 스케일 상한 근거였던 "동시 체류 라이더 최대
   > 244명(K1000)"도 인용 금지 — 큐 자료구조 상한은 **K300 실측으로 재산출**한다.
