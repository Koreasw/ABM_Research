가장 중요한 핵심 철학은 **"거시적(Macro) 2D 외부 데이터와 미시적(Micro) 3D 내부 데이터를 완전히 분리하여 독립적인 확률 모델로 결합하는 하이브리드 접근법"**입니다. 이를 바탕으로 코딩 로직을 4단계로 구조화할 수 있습니다.
________________________________________
단계 1: 2D 데이터 전처리 및 도착 시간 모델링 (외부 환경)
기존의 '식당-고객 간 2D 거리를 3D 층수로 선형 맵핑(Linear mapping)하는 방식'은 현실성 부족으로 폐기되었습니다. 2D 데이터는 오직 배달원 에이전트가 1층 로비에 도착하는 시점과 외부 이동 시간을 결정하는 데만 사용합니다.
•	1-1. 위치 좌표의 단일화 (Point Collapse): 
o	로직: 50개의 서로 다른 2D 고객 위치 좌표는 시뮬레이션 내에서 무의미하므로, 이를 모두 **'가상 10층 건물의 1층 로비(단일 Point)'**로 병합하여 취급합니다.
•	1-2. 도착 패턴 추출 (Poisson Process): 
o	학술적 근거: 세종시 자전거 논문에서 특정 대여소의 사용자 도착을 포아송 과정(Poisson process)으로 가정하여 도달률($\lambda$) 파라미터를 추출한 방식과 동일합니다.
o	코딩 가이드: 배민 데이터의 특정 점심 피크 타임(예: 11:30~13:00) 내 주문 시간(Timestamp) 데이터를 활용하여 **주문 간격(Interarrival time)의 지수 분포(Exponential distribution)**를 도출합니다. 이를 통해 시뮬레이션 상에서 배달원 에이전트가 로비에 생성(Spawn)되는 시간을 스케줄링합니다.
•	1-3. 외부 주행 시간 계산: 
o	로직: 2D 식당-고객 간 거리 데이터는 배달원이 식당에서 1층 로비까지 도달하는 외부 이동 시간(Travel time)을 계산하는 데 활용할 수 있습니다 (로봇 배달 완료까지의 총 소요 시간 지표 계산용).
단계 2: 3D 층수 할당을 위한 확률 모델링 (내부 목적지)
로비에 도착한 에이전트의 최종 목적지(2~10층)는 외부 2D 거리와 철저히 독립되어야 하며, 가상 건물 내부의 인구 통계학적 특성(Population characteristics)에 기반한 확률 난수로 결정합니다.
•	2-1. 범주형 확률 분포(Categorical Distribution) 적용: 
o	학술적 근거: 자전거 논문에서 성별, 연령, 지역 인구 밀도 등에 따라 사용자의 목적지 확률을 다항/범주형 분포로 할당한 것을 벤치마킹합니다.
o	코딩 가이드: 각 층(2~10층)에 수요가 발생할 확률 배열(Probability Array)을 정의합니다. 에이전트가 로비에 도착할 때마다 이 확률 배열을 기반으로 난수(예: Python의 numpy.random.choice)를 발생시켜 목적지 층을 할당합니다.
단계 3: 시나리오 기반 인구 밀도 프로파일 설정 (Control Variables)
층별 수요 발생 확률을 전 층 균등 분포(33.3%)로 설정하는 것은 학술적 타당성이 떨어집니다. 대신 건물의 인구 밀집도(Population density) 비대칭성을 통제 변인으로 설정하여 코딩해야 엘리베이터 병목에 대한 유의미한 스트레스 테스트가 가능합니다.
•	코딩 가이드 (확률 배열 설정 예시): 건물의 층을 저층(2-4F), 중간층(5-7F), 고층(8-10F)으로 그룹화하고, 다음 두 가지 이상의 시나리오를 코드로 구현하여 실험군을 나눕니다. 
o	시나리오 A (저층 집중형 - Bottom-heavy): 저층에 인구가 밀집된 오피스(예: 대형 콜센터). p_bottom_heavy = [0.20, 0.20, 0.20, 0.10, 0.10, 0.10, 0.033, 0.033, 0.033] (2층~10층 확률 합 1.0)
o	시나리오 B (고층 집중형 - Top-heavy): 고층에 인구가 밀집된 오피스. (엘리베이터 왕복 시간이 길어져 로비 병목 현상 극대화 예상) p_top_heavy = [0.033, 0.033, 0.033, 0.10, 0.10, 0.10, 0.20, 0.20, 0.20]
단계 4: 종합 코딩 아키텍처 흐름 (Pseudocode 구조)
이상의 내용을 코딩 아키텍처 흐름으로 요약하면 다음과 같습니다.
1.	데이터 로드 및 파라미터화: 
o	배민 2D 데이터에서 점심 피크 도달률($\lambda$) 추출.
o	건물 인구 밀집도 시나리오(A/B)에 따른 목적지 확률 배열(p_distribution) 로드.
2.	시뮬레이션 루프 (Simulation Loop): 
o	Next_Arrival_Time 산출 (지수 분포 난수 활용).
o	시간 도달 시 1층 로비에 배달원 에이전트 생성(Spawn).
3.	에이전트 목적지 할당: 
o	생성된 배달원 에이전트의 Destination_Floor를 p_distribution을 이용한 범주형 분포 난수로 할당.
4.	Handoff 및 엘리베이터 상호작용 (이후 개발 단계): 
o	배달원이 Handoff 시나리오(Direct, Synchronous, Queued, Lockers)에 따라 로봇/로커 에이전트와 상호작용.
o	할당된 Destination_Floor로 이동하기 위해 엘리베이터 자원(Resource) 대기 및 점유.
요약: 코딩의 시작점은 **1) 외부 배달 도착 시간 생성 함수(포아송/지수 분포 기반)**와 **2) 내부 층수 할당 함수(건물 인구 비중 시나리오에 따른 범주형 분포 기반)**를 독립적으로 분리하여 구현하는 것입니다. 이 체계적인 구조가 완성되면, 이후 Handoff 시나리오와 엘리베이터 대기 큐(Queue) 알고리즘을 붙이는 작업이 훨씬 수월해지며, SCIE 저널이 요구하는 높은 현실성(High-fidelity)을 충족시킬 수 있습니다.
